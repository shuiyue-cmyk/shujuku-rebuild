## 发现

### G11-01 [P3｜已坐实] IDB 写/删失败时 `done` promise 成为未处理拒绝，全局错误捕获多记一条误导性「未处理 Promise 拒绝」（R7-11 修复不完整）
- 位置：`source/src/shared/idb-import-temp.ts:73`（`idbSet_ACU` 的 `const done = idbTransactionDone_ACU(tx);`）、`:83`（`idbDel_ACU` 同款）、`:17-23`（`idbTransactionDone_ACU` 的 onabort/onerror reject）；下游记录点 `source/src/entry-extension.ts:113-119`。
- 触发：外部导入的暂存写入走 IndexedDB 且请求本身失败（配额满、隐私模式、DB 被其它页签升级抢占等）。`store.put` 的 request 先 onerror → `await idbRequestToPromise_ACU(...)` 抛出 → 函数体退出，第 73 行创建的 `done` 无人再挂 handler → 随后事务 abort，`done` 拒绝 → 浏览器上报 `unhandledrejection`。
- 现象：功能面正确（`importTempSet_ACU` 捕获后按设计回退内存暂存并 logWarn），但全局捕获会再记一条 `[全局] 未处理 Promise 拒绝: IndexedDB transaction aborted` 的**错误级**日志（无论 `classifyGlobalErrorOrigin_ACU` 判 own 还是 unknown 都走 logError，只有 foreign 降为警告，而该拒绝源自本插件模块，不会判 foreign），Debug 导出里出现一条与真实故障（IDB 不可用）无关的吓人条目。
- 原因：R7-11 修复「只等 request 成功、不等事务 complete」时引入 `done` 前置创建，但没有给失败路径兜底：
  ```ts
  const done = idbTransactionDone_ACU(tx);
  const store = tx.objectStore(IMPORT_TEMP_STORE_NAME_ACU);
  await idbRequestToPromise_ACU(store.put(value, key));  // 这里抛出后，done 悬空
  await done;
  ```
- 已排除：查了 `idbSet_ACU`/`idbDel_ACU` 的全部调用方（`importTempSet_ACU`/`importTempRemove_ACU`/`importTempGet_ACU`，均 try/catch，功能回退正常）；确认拒绝确实无人处理（探针复现）；确认 entry 的 `unhandledrejection` 监听会把它记为错误。
- 测试：`tests/shared/idb-import-temp.test.ts` 只测了「request 成功但事务中止」（该路径 `await done` 已挂 handler，拒绝被调用方接住），没测「request 自身失败」的悬空路径，所以没拦住。
- 修法方向：创建后立即 `done.catch(() => {})` 预挂空 handler（或 `Promise.all([reqPromise, done])` 一并 await），失败语义不变。
- 与上一轮复审的关系：**R7-11 修复不完整**（修复本身引入的残留）。

## 设计层面的疑虑（不计入缺陷）

1. **INSERT 列名前缀自动纠正的误导向残余风险**（`sql-mutation-table-rebind.ts:415-428`，提交 cf314c2d 的明确产品决定）：当模型把一个**表里根本不存在**的列名写短、且短形恰好是唯一某真实列的前缀时（如臆想列 `attack_power` 写成 `attack`，表里只有 `attack_speed`），值会被写进 `attack_speed` 而不是被拒绝——静默进了错列。需要「臆想列 + 恰好截短 + 唯一前缀 + 不与清单重复」多重巧合，且有唯一性与重复守卫，故不算缺陷，但与本文件头注释「别名表查不到 → 原样保留，交给 SQLite 报真实 no such column（无证据不猜）」的 fail-closed 哲学存在张力，建议在注释里写明这是有意例外。
2. **日志归一把任何带 `message`/`stack` 字符串字段的对象当 Error 处理**（`log-buffer.ts:179-191`）：跨 realm Error 捕获是合理动机，但普通对象 `{message:'x', detail:{...}}` 会只留 `Error: x` 而丢掉其余字段的日志保真。仅影响诊断信息，不影响功能。
